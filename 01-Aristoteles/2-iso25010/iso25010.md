# Oportunidades de mejora de ARISCON según ISO 25010

## 1. Contexto

ARISCON es el sistema principal de información de ARISTO y cumple funciones académicas, comunicacionales, administrativas y operativas. Sin embargo, su estado actual presenta varios problemas de calidad del software que afectan directamente la operación escolar, la reputación institucional y la seguridad del sistema.

## 2. Análisis por características ISO 25010

### 2.1 Adecuación funcional

Oportunidades de mejora:

- Unificar la funcionalidad entre web, móvil y web administrativa; hoy algunos procesos solo existen en una interfaz.
- Centralizar la lógica de negocio para evitar que una operación se haga en un sistema y no en otro.
- Definir un modelo único de dominio para matrícula, notas, tareas, asistencia, mensajes, reportes y seguridad.

Riesgo actual:

- Hay inconsistencias entre aplicaciones, porque cada una fue desarrollada por distintos proveedores y con bases separadas.

### 2.2 Eficiencia de rendimiento

Oportunidades de mejora:

- Diseñar una arquitectura con balanceo de carga, caché, escalado horizontal y optimización de consultas.
- Optimizar la carga concurrente durante fechas críticas (ingreso de notas, consultas de padres y alumnos).
- Definir SLAs de tiempo de respuesta; el objetivo de 5 segundos debe medirse y validarse en pruebas de estrés.

Riesgo actual:

- La Web tuvo caídas durante tres días por alta concurrencia; además, el registro de notas se retrasó por lentitud.

### 2.3 Compatibilidad

Oportunidades de mejora:

- Estandarizar APIs REST/JSON y contratos de integración para todos los canales.
- Unificar la experiencia en web y móvil con una misma lógica de negocio.
- Reducir la dependencia de múltiples bases de datos y sistemas de seguridad por aplicación.

Riesgo actual:

- Las aplicaciones fueron construidas en distintos momentos y con tecnologías dispares, lo que afecta interoperabilidad y consistencia.

### 2.4 Usabilidad

Oportunidades de mejora:

- Diseñar una experiencia visual consistente con los colores corporativos de ARISTO.
- Mejorar la navegación, mensajes, indicadores de carga y estandarización de componentes.
- Centralizar una guía de estilo UX/UI, con patrones y nomenclatura uniforme.

Riesgo actual:

- La interfaz es diferente entre sistemas y las aplicaciones móviles son confusas y difíciles de usar.

### 2.5 Fiabilidad

Oportunidades de mejora:

- Aplicar patrones de tolerancia a fallos y recuperación ante incidentes.
- Mejorar la consistencia transaccional y la detección de operaciones incompletas.
- Implementar monitoreo, alertas y restauración automática de servicios críticos.

Riesgo actual:

- Existen transacciones que se graban en un sistema y no se visualizan en otro.
- El sistema tuvo un incidente grave con caída y restauración desde backup antiguo.

### 2.6 Seguridad

Oportunidades de mejora:

- Reemplazar la seguridad ad hoc por un modelo común de identidad, autenticación, autorización y auditoría.
- Incorporar autenticación robusta con MFA, controles de password según estándares y políticas de seguridad.
- Usar WAF, firewalls, parches, cifrado, gestión de secretos y registro de auditoría por operación.
- Definir controles contra ataques de inyección, XSS, MITM y DDoS.

Riesgo actual:

- El ataque con contenido pornográfico evidenció vulnerabilidades en la capa web y en la gestión de contenido y seguridad del sistema.
- Usuarios, claves y permisos estaban fragmentados por aplicación.

### 2.7 Mantenibilidad

Oportunidades de mejora:

- Reducir el technical debt identificado por SonarQube.
- Establecer estándares de programación, arquitectura, datos y calidad.
- Definir una base común de componentes reutilizables y un pipeline de CI/CD.
- Adoptar arquitectura modular o microservicios orientados a dominios y no a clientes aislados.

Riesgo actual:

- El código es complejo, difícil de seguir y difícil de mantener. El analista encontró una gran cantidad de deuda técnica.

### 2.8 Portabilidad

Oportunidades de mejora:

- Migrar el stack actual a una arquitectura cloud nativa con servicios administrados y con compatibilidad con el crecimiento proyectado.
- Modernizar Windows Server 2012, SQL Server 2012, IIS y .NET 4.6.
- Preparar el sistema para soportar nuevas plataformas y dispositivos sin reescribir la lógica desde cero.

Riesgo actual:

- La solución depende de tecnologías y sistemas legacy que ya están desactualizados.

## 3. Prioridad de mejora

Las cinco áreas más críticas a resolver son:

1. Seguridad.
2. Fiabilidad y disponibilidad.
3. Mantenibilidad y deuda técnica.
4. Rendimiento y escalabilidad.
5. Integridad funcional y consistencia de datos.

## 4. Conclusión

La principal mejora de calidad que requiere ARISCON es pasar de una solución fragmentada, legacy y vulnerable a una arquitectura digital moderna, escalable y segura. La calidad del software se ve afectada principalmente por los problemas de seguridad, consistencia de datos, mantenibilidad y desempeño, todos ligados a la falta de estándares y una arquitectura unificada.
